# MEMORIA 1.0.10 코드 리뷰 및 정리

검토일: 2026-09-06 KST
기준 커밋: fd3cd2f (develop)
범위: 앱 UI·저장·학습·파일 처리·동기화, 번역, 설정·의존성 및 기존 인수인계.

## 수정한 동작

| 문제 | 변경과 확인 |
| --- | --- |
| 내보낸 CSV/Excel이 번호와 폴더를 카드로 다시 읽음 | MEMORIA 헤더로 Front/Back 내용 복원. CSV의 앞자리 0·날짜 형태·줄바꿈 보존. CSV/XLSX 왕복 검사 |
| 폴더가 다른 동일 카드끼리 통계와 숨김 공유 | 폴더+내용 기반 v2 키 도입. 기존 공유 기준치는 기존 카드 각각에 보존하고 이후 기록 분리 |
| 편집·이동 시 다른 카드 숨김이 사라짐 | 대상 카드만 기록 이전. 오답 기록에 카드 ID와 폴더 보존 |
| 오답 복습이 다른 폴더의 같은 내용에 연결될 수 있음 | ID·폴더 키 순서로 조회. 폴더 정보가 없는 과거 기록은 유일한 카드일 때만 연결 |
| C++와 C, 숫자가 다른 답안을 정답 인정 | 숫자·의미 있는 기호는 정확 비교. 자연어의 대소문자·띄어쓰기·조사·작은 오타 허용 유지 |
| 완료 후 돌아가면 학습 기록이 되돌아감 | 완료한 회차의 되돌리기 스냅샷 해제. 같은 정답 제출 중복 집계 차단 |
| 초기 로드에서 숨김 상태 유실 가능 | 카드 로딩 후 통계 정규화. 읽기 실패 시 저장 활성화를 늦추고 재시도 안내 |
| 동시에 저장한 카드나 계정 전환 중 응답이 섞임 | 저장 직렬화, 제출 시 계정 캡처, 수정·삭제 응답의 계정 검사와 최신 배열 사용 |
| 대량 cloud 조회 누락 또는 늦은 응답이 상태 덮어쓰기 | 사용자별 ID 커서로 빈 페이지까지 조회. 중간 오류·계정/로컬 변경 시 적용 취소 |
| cloud 학습 저장 순서 역전 | 학습 저장 큐 직렬화. 새 pull 전에 제출된 쓰기 완료 대기 |
| 모바일 보관함 제목이 한 글자씩 줄바꿈됨 | 제목 아래 관리 버튼 배치, 버튼 줄바꿈 허용 |

앱 정보에 **지금 동기화** 버튼을 추가했다. 카드 내용 내보내기는 읽기 쉬운 표이며, 가져오기에서 폴더 구조·통계·숨김을 복원하는 전체 백업으로 표시하지 않는다.

## 정리 범위

- 미사용 스타일 138개, App 선언 3개, 이전 출제 보조 함수 2개, 튜토리얼 인자 2개 정리.
- 내보내기 열 구성과 cloud 전체 조회를 독립 모듈로 분리.
- 기존 5개 탭과 폴더 관리 기능 유지. README·handoff·출시 노트 갱신.
- Expo SDK 54 유지: Expo 54.0.37, expo-file-system 19.0.24. 중복 네이티브 모듈 정리.
- 호환 범위의 전이 의존성 보안 패치 적용. 새 기능용 의존성 추가 없음.

## 검증 결과

- npm test: **58/58 통과**. App 핸들러를 AST로 추출해 계정 전환·동시 저장·삭제·완료 기록·초기 복원·cloud 저장 순서를 검사하고, 파일·학습 모듈을 직접 실행했다.
- npm run typecheck 및 Babel 파싱 통과. checkJs=false이므로 JavaScript 전체 타입 검증은 아님.
- Expo Doctor **18/18 통과**. SDK 버전 및 중복 네이티브 모듈 검사 포함.
- 스타일 정의와 참조 각각 600개, 미참조·누락 없음. ko/en/ja 각각 번역 키 586개 일치, 정적 번역 호출 342개 모두 존재.
- Android export로 네이티브 대상 JS/Hermes 번들 생성 확인. 설치 가능한 APK/AAB 빌드와는 별개.
- 계정 설정을 제외한 별도 브라우저에서 게스트 시작, 카드 저장, 기호 정오답, 완료 기록과 오답 복습을 조작했다.
- 최종 화면에서 저장·숨김과 reload 후 숨김 복원을 확인했다. 390×844와 768×1024, 한국어·영어 및 라이트·다크 테마를 확인했으며 브라우저 실행 오류는 없었다.
- 화면 증거는 Git에서 제외된 .expo/review-*.png에 있다. 서버 재시작 시 검증 브라우저 프로필이 새로 열렸으므로 영속성 결과는 같은 프로필의 reload 검사에 근거한다.

## 남은 검증과 운영 범위

- Expo Go SDK 54 실기기 조작은 미완료. 연결 후 저장·파일 선택·학습·숨김·재시작을 확인해야 한다.
- 실제 Google 인증, 다중 기기 동기화, 알림, 계정 삭제와 문의 권한은 development/preview build 및 테스트 계정으로 검증해야 한다. 이번 cloud 테스트는 mock 경계 검사다.
- 운영 Supabase SQL 적용과 Google Play 배포는 수행하지 않았다. 이전 20260727_harden_account_and_data.sql 적용 상태부터 확인한다.
- 기존 공유 통계는 폴더별 과거 횟수로 역분해할 정보가 없어 기존 표시값을 각 카드에 유지한다. 새 v2 키를 모르는 구버전과의 혼용까지 무손실 호환을 보장하지 않는다.
- npm audit는 30개에서 **22개(중간 13, 높음 9)**로 감소했고 critical 항목은 해소했다. 남은 근본 항목은 SDK 54 도구 체인의 image-size·postcss·uuid이며 상위 패키지 경고에 중복 전파된다. 감사 도구의 강제 수정은 SDK 57 변경이므로 SDK 54 조건을 유지했다.
- 감사 근거: [image-size](https://github.com/advisories/GHSA-w3rx-r6r6-pgpr), [PostCSS](https://github.com/advisories/GHSA-fxqj-rqcc-2cmp), [uuid](https://github.com/advisories/GHSA-w5hq-g745-h8pq). 앱 입력으로 악용되는지를 입증한 침투 테스트 결과는 아니다.
- 사용자 참고 파일 want.png는 변경·스테이징하지 않는다.

## 후속 아이디어

언어·자격증별 샘플 카드 묶음을 제공하면 첫 실행에서 직접 입력하기 전에도 학습 가치를 경험할 수 있다. 이번 수정에는 콘텐츠 배포나 공유 서비스를 추가하지 않았다.
